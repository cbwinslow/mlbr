mlbr: Production Sabermetrics Data Lake

High-performance, zero-copy analytics and machine learning over complete MLB history

mlbr Data Lake & Sabermetrics Platform

Zero-copy Apache Parquet storage, unified DuckDB querying, and machine learning pipelines across 150+ years of baseball data.

Executive Overview

mlbr is a production-grade analytical platform and R package designed for large-scale baseball analytics, empirical sabermetrics, and machine learning. Built on top of cbwdellr720 (40 Xeon cores, 125 GB RAM, high-speed NVMe/HDD storage), mlbr unifies:

  • 150+ Years of Retrosheet Play-by-Play (1871–2025): Every pitch, hit, out, substitution, and umpire event parsed directly via Chadwick C tools.
  • Complete Statcast Pitch Tracking (2008–2026): Per-pitch Hawkeye/PITCHf/x metrics (velocities, spin rates, release coordinates, 3D break profiles).
  • Comprehensive FanGraphs Historical Records (1901–2025): Advanced leaderboards, Stuff+, PitchingBot, Gut constants, and park factors.
  • Chadwick Bureau Register: Universal cross-identifier mapping covering >527,000 players across MLB, MiLB, Retrosheet, Baseball-Reference, and Fangraphs.
  • NCAA & Minor League (MiLB) Data: Extended feeder systems and collegiate play tracking.

NoteZero-Drop Column Invariant

In traditional analytics pipelines, downstream transformations often drop columns considered non-essential at ingestion time. mlbr enforces a strict Zero-Drop Column Invariant: 100% of available raw columns (e.g., 119 in Statcast, 160 in Retrosheet events, 447+ in FanGraphs) are preserved in parquet partitions.

Platform Architecture

mlbr utilizes a decoupled Lake-Warehouse architecture:

[ Data Providers ]
  ├── MLB Savant (Statcast per-pitch API)
  ├── Retrosheet / Chadwick Bureau (Git mirror & C tools)
  ├── FanGraphs (Leaderboards & Sabermetric Constants)
  └── Lahman / NCAA / MLB Meta
          │
          ▼
[ Ingestion & Adaptive Tier Ladder ] (R/ingest/*.R)
  - Month -> Week -> Day fallback (eliminates 25,000 row caps)
  - Exponential backoff & polite rate limiting
          │
          ▼
[ Storage Layer ] (data/raw/*.parquet)
  - Columnar Apache Parquet partitions
  - ZSTD / Snappy compression, dictionary encoding, sorted row groups
          │
          ▼
[ Zero-Copy Analytical Engine ] (DuckDB + mlbr R package)
  - Out-of-core streaming execution
  - Vectorized SIMD query processing
  - Direct integration with dplyr, tidymodels, and ggplot2

Quickstart

1. Zero-Copy DuckDB Query

Mount the entire multi-million row data lake in milliseconds without loading files into RAM:

library(mlbr)
library(dplyr)

# Connect to DuckDB with pre-mounted views
con <- lake_duckdb()

# Query pitch velocity distribution
top_heat <- tbl(con, "v_statcast_features") %>%
  filter(release_speed > 102) %>%
  select(pitcher, pitch_type, release_speed, ivb_in, vaa, release_spin_rate) %>%
  arrange(desc(release_speed)) %>%
  head(10) %>%
  collect()

print(top_heat)

2. Lake Health & Verification

Run the automated 28-point invariant proof suite:

res <- proof_lake()
# Output: 28 / 28 passed (100.0%) in ~4.3 seconds
